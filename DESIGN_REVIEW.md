# Design Review — SIMOGRANTS Frontend

Reviewed against the [Anthropic Frontend Design Skill](https://github.com/anthropics/claude-code/blob/main/plugins/frontend-design/skills/frontend-design/SKILL.md) criteria: typography, color/theme, motion, spatial composition, backgrounds/visual details, and overall aesthetic identity.

---

## Overall Verdict

The frontend is **functionally competent but aesthetically generic**. It falls squarely into the "AI slop" category the design skill warns against: Inter font, purple-to-cyan gradient on dark slate, predictable card layouts, and zero visual surprises. Every page looks like it was generated by asking an AI to "make a dark mode Web3 dashboard." There is no distinctive design identity.

---

## Typography

### Current State
- **Font:** Inter (loaded from Google Fonts, `globals.css:4`)
- **Usage:** `font-extrabold` for headings, `font-semibold` for subheads, `text-sm` for body
- **index.html:10:** `Inter:wght@300;400;500;600;700;800;900` — loads 7 weights of a single generic font

### Problems
- **Inter is the #1 most overused font in AI-generated interfaces.** The design skill explicitly calls it out: "NEVER use generic AI-generated aesthetics like overused font families (Inter, Roboto, Arial, system fonts)."
- **No display font.** The hero title "SIMOGRANTS" at `text-7xl font-extrabold` uses the same Inter as body copy. A distinctive display or monospace font would give the brand its own voice.
- **No font pairing.** Every element — nav, hero, cards, data tables, footers — uses the same typeface at different weights. This flattens the visual hierarchy.
- **Tracking is default.** Only `tracking-tight` on the hero title and `tracking-wider`/`tracking-widest` on tiny labels. No considered letter-spacing strategy.

### Recommendations
- Replace Inter with a distinctive pair: a characterful display font for the brand name and headings (e.g., Space Mono, Instrument Serif, Bricolage Grotesque, Clash Display) paired with a clean text font for body (e.g., Outfit, Satoshi, General Sans).
- Use the display font sparingly — hero, section headings, the "S" logo mark.
- Add `font-feature-settings` for tabular numbers in score/allocation displays.

## Color & Theme

### Current State
- **Primary palette:** `violet-400` through `violet-900` with `cyan-400`/`cyan-500` accents
- **Background:** `slate-900` base, `slate-800/50` cards, `slate-700/50` borders
- **Gradients:** `from-violet-600 to-cyan-500` on CTAs, `from-violet-400 via-blue-400 to-cyan-400` on text
- **Semantic colors:** `emerald-400` (positive), `amber-400` (warning), `red-400` (error), `blue-400` (info)
- **CSS variables:** `globals.css:4-14` defines `--color-primary-50` through `--color-primary-900` (standard violet Tailwind scale) but these are **never used** — everything uses Tailwind utility classes directly.

### Problems
- **"Purple gradient on dark background" is the most cliched AI-generated Web3 aesthetic.** The design skill warns: "cliched color schemes (particularly purple gradients on white backgrounds)" — the dark variant is equally overused.
- **The violet-to-cyan gradient appears everywhere**: hero title, CTA buttons, stat numbers, feature icon backgrounds, logo mark, nav active state. Overuse dilutes impact.
- **No color hierarchy.** Every accent competes for attention equally. There's no clear primary/secondary/tertiary color distinction.
- **Custom CSS variables defined but unused.** The `@theme` block in `globals.css` is dead code.
- **Opacity soup.** The card system uses `bg-slate-800/50`, `bg-slate-800/30`, `border-slate-700/50`, `bg-violet-600/20`, `bg-violet-500/10`, etc. The layered transparencies create muddy, indistinct surfaces instead of clear depth.

### Recommendations
- Pick a bolder, less expected palette. For a project about "stigmergic intelligence" (ant colonies), consider warm earth tones (amber/terracotta/forest) or a high-contrast editorial palette (near-black + one accent).
- Reduce gradient usage to 1-2 hero elements. Use solid accent colors for CTAs.
- Clean up the opacity system: define 3-4 distinct surface levels with solid or near-solid colors.
- Remove unused CSS variables or actually use them as the single source of truth.

## Motion & Animation

### Current State
- `animate-pulse` on 3 background orbs in hero (Landing.tsx:89-91) and the green connection dot
- `animate-gradient-x` on the hero title (6s ease infinite, `globals.css:34-37`)
- `transition-all duration-300` on card hovers
- `transition-colors` on links/buttons
- `hover:scale-[1.02] active:scale-[0.98]` on CTA buttons
- `transition-all duration-700 ease-out` on ScoreBar/AllocationBar fill
- Defined but unused: `animate-fade-in`, `animate-pulse-glow`, `.page-enter`/`.page-enter-active`

### Problems
- **`animate-pulse` on the orbs is the default Tailwind pulse.** Slow, repetitive, and feels like a loading indicator rather than atmosphere.
- **No page transitions.** The `.page-enter` class is defined in CSS but never applied. Navigation is abrupt — instant content swap with no orchestration.
- **No staggered reveals.** Cards, stats, and features all appear simultaneously. The design skill emphasizes: "one well-orchestrated page load with staggered reveals (animation-delay) creates more delight than scattered micro-interactions."
- **No scroll-triggered animations.** All content below the fold is static. No reveals on scroll.
- **The ScoreBar 700ms fill animation is nice** — one of the few intentional motion moments — but it fires on initial render without an intersection observer, so users never see it animate.

### Recommendations
- Add staggered fade-in on card grids using `animation-delay` (e.g., cards enter 0ms, 100ms, 200ms).
- Replace `animate-pulse` on orbs with a slower, more organic float/drift animation (`translateY` + slight scale).
- Implement `IntersectionObserver`-triggered reveals for below-fold content — the stats, features, and "How It Works" sections.
- Use the already-defined `animate-fade-in` class — it's written but never applied anywhere.
- Add a subtle page transition between routes (fade or slide).

## Spatial Composition & Layout

### Current State
- `max-w-7xl mx-auto` container on every section
- Standard symmetric grid: `grid-cols-1 md:grid-cols-3` for features, steps; `grid-cols-2 sm:grid-cols-4` for stats
- Cards are uniform rectangles: `rounded-xl border p-5` or `p-8`
- Centered text alignment for hero, section headers, and "How It Works"
- Footer uses a 3-column grid

### Problems
- **Every section follows the exact same pattern:** centered header (h2 + subtitle) → 3-column grid → repeat. This creates a monotonous vertical rhythm.
- **No spatial surprises.** The design skill calls for "unexpected layouts, asymmetry, overlap, diagonal flow, grid-breaking elements." Nothing here breaks the grid.
- **The hero is a centered text block** — the most predictable hero layout possible. No visual element (illustration, 3D, data viz) to anchor attention.
- **The "How It Works" connector lines** (Landing.tsx:196-197) are a good idea but executed as simple horizontal divs. They don't curve, animate, or feel organic.
- **Uniform card sizing.** All feature cards, round cards, and result rows are identically sized. No visual hierarchy between items.
- **No negative space strategy.** Padding and margins are consistent (`py-20 sm:py-28`, `gap-6`, `gap-8`) — functional but unremarkable.

### Recommendations
- Break the symmetric grid in at least one section: offset cards, overlapping elements, or a 2/1 split layout.
- Add a visual anchor to the hero: an abstract data visualization of the pheromone/QF mechanism, a stylized ant colony pattern, or a live animation of the evaluation agents.
- Make the "How It Works" connector lines animated (SVG path drawing or dashed pulse).
- Vary section padding and rhythm — tighter sections between spacious ones.
- Consider making the top-ranked project in results visually larger/different from the rest.

## Backgrounds & Visual Details

### Current State
- Hero background: triple-layer gradient (`from-violet-900/40 via-slate-900 to-cyan-900/40`) + radial gradient + 3 blurred orbs
- Section backgrounds: `bg-slate-800/20` (stats bar), otherwise transparent on `bg-slate-900`
- Cards: `bg-slate-800/50` or `bg-slate-800/30` with `backdrop-blur-sm`
- No textures, patterns, noise, or grain
- No illustrations or icons beyond inline SVGs
- Favicon: default Vite icon (`/vite.svg`)

### Problems
- **The gradient orbs are the only atmospheric element** and they feel like every other Web3 landing page.
- **No texture or grain.** The surfaces are flat gradient fills. A subtle noise overlay or fine-grained texture would add depth.
- **The "S" logo is a letter in a gradient box** — not a designed mark. It appears in the nav, hero, and footer but is just `text-xs font-bold "S"`.
- **Default Vite favicon.** This is the blue Vite lightning bolt, not a SIMOGRANTS brand mark.
- **No visual metaphor for stigmergy.** The concept is about ant pheromone trails, but nothing in the UI visually references trails, networks, paths, or organic colony patterns.
- **`backdrop-blur-sm` is overused.** Applied to cards, nav, and mobile menu — adds subtle GPU cost for negligible visual benefit at low opacities.

### Recommendations
- Add a subtle noise/grain overlay to the background (`background-image: url(noise.svg)` at 2-5% opacity).
- Design a proper brand mark — even a simple geometric "S" with trail/pheromone visual language.
- Replace the Vite favicon with the brand mark.
- Add a topographic/network-line pattern to section backgrounds — subtle but thematic.
- Consider a pheromone trail visualization: animated SVG paths connecting the "How It Works" steps, or a subtle network graph in the hero background.
- Remove `backdrop-blur-sm` from cards where it's not visually impactful (most of them).

## Component-Level Design Notes

### RoundCard
- Functional but generic. Every card is identical in visual weight.
- Hover effect (`border-violet-500/50` + `shadow-violet-500/10`) is barely perceptible.
- No visual indicator of round health/urgency (days until deadline, % filled).

### ScoreBar / AllocationBar
- Clean implementation. The gradient fill + score-based color coding (green/blue/amber/red) is effective.
- Hardcoded `USDC` label in AllocationBar should come from data.
- No number formatting for very large values.

### StatusBadge
- Review needed to check if all statuses have distinct visual treatments.

### ConnectButton
- Gradient button is clean. Connected state (green dot + truncated address) is standard Web3 UX.
- The `setTimeout(() => signIn(), 500)` is a hack. Should use wagmi's `onSuccess` properly.

### LoadingSkeleton
- Review needed. If it's just `animate-pulse` blocks, consider shimmer animations instead.

## Priority Recommendations

### 1. Typography (Highest Impact, Lowest Effort)
Replace Inter. Load a distinctive display font and a refined body font. This single change would immediately differentiate the product.

### 2. Brand Identity
Design a proper logo mark that references stigmergic intelligence (trails, networks, emergence). Replace the Vite favicon. Establish visual language.

### 3. Hero Section
Add a visual anchor — an animated data visualization, network graph, or stylized pheromone trail illustration. The hero is currently just text.

### 4. Color System Overhaul
Move away from the violet-cyan gradient everywhere. Pick a less expected palette. Use gradients sparingly for maximum impact.

### 5. Motion System
Implement staggered card reveals, scroll-triggered animations, and page transitions. The CSS is already half-written (`animate-fade-in`, `.page-enter`) — just not connected.

### 6. Texture & Atmosphere
Add noise/grain overlay. Introduce a thematic background pattern. Remove reliance on blurred orbs as the only atmospheric element.
